# Fresh-world runner

`cohort.py` is trusted supervision around the already executed integration
commands. The unchanged financial worker, MPC Source04, all-nine host check and
scorer Source02 perform the actual work. The new files implement scheduling,
typed public promotion and the frozen statistical calculation. They introduce
no financial relation, setup, shuffle, observer strategy or truth API.

The frozen contract is `research/next-session/owner-private-prototype/COHORT-CONTRACT-01.md`
(SHA256 `28a3b29edff91634e193d28ed7b4914b1216d84bf6200c210899e967870016c2`).
`COHORT-SPEC-03.json` selects sixteen world IDs, the original public setup,
reviewed source manifests, genuine image/template and selected executable bytes.
It contains no owner identity, private directory, payment plan or hidden map.

1. Run the command below without `--execute`. It checks the source/asset
   selections in seconds and creates no runtime directory or owner.
2. Root reviews the additive source/spec. Wait for the existing outer/native
   lane to finish before starting any new heavy owner proving.
3. Run the same command with `--execute`. It registers all sixteen identities
   before initializing the first owner and processes the worlds in that order.

  --spec poc/owner-private-payments/integration/COHORT-SPEC-03.json

Each world creates new private party parents and initializes fresh seeds,
participant IDs and commitments inside three separate owner workers. It then
builds a new genesis/context/session, compiles that actual session, creates six
real Output proofs privately, runs the actual MPC, builds the real public body,
collects three postmix Spend proofs, and requires the independent all-nine host
cross-check. Payment destination and amount selection remain owner-local.
Original public commitments, NFs, participant IDs and session digests cannot be
reused across cohort worlds. The completed exploratory world stays excluded.
The native projection uses the selected image and B1800/F19332300 template;
its zero outer-proof placeholder never counts as native or chain acceptance.

The two old trial roots and every retained/new party/controller private branch
are metadata exclusions before generic public reads. Inode exclusions persist
across refreshes, including every current controller PRIVATE plan/log inode.
Only an exact registered producer public leaf that was never observed private
may be exempted from new private-inode additions; an existing forbidden inode
is never removed. Snapshots occur both before and after each child phase.
Inner unchanged commands still receive exactly their own
three party parents. A narrow producer route reads only a registered current
job's `public/PUBLIC.json`, validates its exact typed schema and promotes it to
the world's public directory. Generic ingress cannot read controller plans,
logs or private branches. No seed, invoice, TRUTH, capsule, count leaf, MPC
input, raw engine log or direct own-engine report is host-read, copied or
hashed. The only direct report operation is the previously required metadata
chmod0644→0400 before owner authorization. Diagnostics use the original
owner-local capsule and count leaf handles directly.

Worlds run serially. Three owners run together under one 14CPU/20GiB cgroup
for Output or Spend proving. They never overlap active MPC engines. Public
compiler/light stages use 4CPU/4GiB; the MPC controller uses1CPU/512MiB and
the unchanged containers/anchor retain their original caps (total3.8CPU/3616MiB).
The installed systemd/Python helper records actual own-cgroup limits/counters;
the selected MPC backend separately records owned-container counters/cleanup.
No timeout in this wrapper turns a strict check into acceptance. Operational
MPC failure halts further execution to avoid overlap with unknown cleanup,
retaining all unattempted registered slots as INCOMPLETE. Other failures retain
their world without replacement; a score or unique-group failure does not stop
the remaining worlds. Raw child diagnostics stay controller-private.
An ordinary rejection, process error or missing file is classification-pending
INCOMPLETE; it establishes neither candidate safety nor invalid financial
acceptance. A separate typed `ConfirmedFalsification` path records a trusted
explicit invalid-acceptance, double-spend or direct-disclosure verdict as
CANDIDATE_FAIL. A child error string cannot select that path. The current
joined unique-group diagnostic also remains an explicit candidate failure.

After each financial cross-check, the coordinator prediction is sealed, the
fixed roster0 colluder observes once, and the bundle is sealed before each
owner scores once. Only the global counts are promoted. `cohort_stats.py`
checks joined contexts and presealed ambiguity, then uses sixteen world events
and exact rational Poisson-binomial arithmetic. K1/unique grouping fails before
unexpected shape handling; groupcount1 remains INCOMPLETE. Missing worlds
cannot shrink the denominator. A complete comparison without excess success
is a bounded negative result under an explicit conditional-uniform independent
world model, and never qualifies privacy or financial acceptance.
