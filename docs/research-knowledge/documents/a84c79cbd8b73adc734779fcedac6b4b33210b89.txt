# HTTPS/CAS retrieval controls

Frozen before execution, under the root's practical transport addition release.
Eight cases target the real production `https_mirror.retrieve_capsule` and its
redirect policy using tiny public non-Ark fixtures and local HTTP servers.

1. Stop the preferred server, retrieve all exact bytes through the fallback.
2. Reject corrupted primary objects and retrieve matching fallback objects.
3. Recognize/stage public history with no PK object and no PK HTTP request.
4. All missing mirrors return incomplete without current/spend authorization.
5. Reject insecure external HTTP, credential/query/fragment initial URLs and
   HTTPS downgrade; allow cross-origin HTTPS redirect configuration.
6. Reject wrong-role manifest before requesting the large PK object.
7. Exercise actual literal-loopback redirects; omit URL/query strings from reports.
8. Reject truncated response; retry the entire exact object without prefix splicing.

Literal-loopback HTTP is explicitly enabled only for these tests. They do not
exercise a real external TLS server, provider retention, independent hosts,
actual Ark PK decoding, private backup recognition, native validation or payout.
Verified HTTPS is the production policy; no TLS bypass is added. The capsule
core's prior 12/12 source controls are preserved and not rerun merely for count.
Record failures without retuning the frozen outcomes. No upload/paid service or
actual large-object retrieval is authorized by this run.
