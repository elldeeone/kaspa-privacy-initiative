# Ordinary mined-test-KAS acquisition

This is an ordinary funding transaction, separate from the shielded protocol. It spends only mature native P2PK coinbases belonging to one selected original A funding key. It creates exactly 21 KAS at each externally selected fresh A and C script, and optionally returns the remainder to the same A script. It cannot spend a pool UTXO or covenant, select an arbitrary recipient, or use the shielded seed or a proving key.

The financial profile stays fixed. The constructor receipt hash and trial identity are externally selected metadata, so creating a fresh unfunded trial does not require a new setup or source edit. The first actual invocation must use the specifically approved constructor receipt. The receipt supplies both ordinary destinations; the refund must use its A source script. The one original backup is selected by the caller's reviewed LIVE trial directory and is mounted only for the offline signer.

All original LOCAL and LIVE backup inodes and complete owner directories are excluded before public ingress. The launcher authenticates the frozen closed-staging helper, selected 68-file software inventory, exact fixed source/runtime/SDK closure and externally pinned new five-file source freeze. The host never opens, copies or hashes an original backup. Worker paths are synthetic and network-off for quotes and signing. Only one A backup is mounted for signing. Its strict existing compound parser exposes the independent ordinary funding scalar inside that worker; no root-seed derivation or new cryptography is introduced.

Each input is a positive ordinary A P2PK coinbase with no covenant, a unique sorted outpoint, compute budget 10 and final sequence. Actual node DAA must be at least the source DAA plus 1000. This maturity is the selected 10-block-per-second testnet parameter (rusty-kaspa commit `4edcbbccb449f84832afb1ca157904b35f37d006`, config/bps.rs and constants.rs; testnet params block rate 10). Amounts are integer sompi; decimal strings exist only at SDK/RPC boundaries.

The Native normalizer supplies mining mass. Exact fee is 100 times that mass. Fixed 66-byte ALL-shaped placeholders allow quoting the eventual signature lengths. The signer repeats normalization and the complete output, input, maturity-observation and fee policy before its first private read. It signs every A input using the selected SDK's established `createInputSignature` and `SighashType.All`, then requires an unchanged normalized body and fresh Native Full acceptance of every input engine. The generic frozen helpers that reject coinbases or require two inputs are not weakened.

Submission performs another complete closed Native/SDK check and queries the actual selected outpoints, amounts, scripts, birth DAA, coinbase flags and covenant flags at a synced TN10 node. After this query the host durably creates one exclusive immutable intent in the selected constructor namespace. The network worker then repeats the exact query before making one submission RPC. A missing, failed or ambiguous response consumes the intent and permits only read-only reconciliation. No automatic resend or replacement exists. A fresh trial means a fresh constructor namespace.

Reconciliation observes every exact intended ordinary output UTXO at the trusted node. This is explicitly a node observation, not a complete accepted-history proof. Its separate acquisition ledger records the selected coinbase sum, acquisition fee, two ordinary funding outputs and protected refund. Mining rewards add no useful private-payment principal to the later payment ledger. Subsequent GN2/W accepted-prefix and confirmed-exit checks remain mandatory.

The ordinary RPC shares only the network and read-only software with the host. It receives public data and has no private-key/signing dispatch. Public and private controller artifacts remain outside Git. In particular, plans, raw arguments, actual cases and actual identity/provenance joins are not automatic publication artifacts.

Current evidence is source only. Synthetic policy controls are authored but not executed. No new SDK, Native, backup read, signing, mining or transaction submission is authorized by this document. Root source review and a second pass precede private signing or submission.
