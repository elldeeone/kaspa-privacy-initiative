Status: the actual static HTTPS retrieval and closed recorded-GN3 replay pass.
The complete accepted round-two data selection and cold exit campaign remain

## Public objects and byte authority

The immutable static release contains 18 objects, including all three complete
parameter families and the 63-file software archive. The complete experiment
will retrieve its selected objects once with the unchanged pinned HTTPS
transport into one fresh public store. Three fresh owner namespaces may share
that authenticated public store read-only; there is no per-owner download.

The original source/repository/cache/private/PK paths must be absent inside
every replay, public case-construction and owner namespace. A reused public
store of bytes actually retrieved from GitHub is explicitly identified. The
original Forge and release have the same administrator. Neither immediate
retrieval nor three namespaces proves separate administration or retention.

The existing closure schema and its 18 required roles remain unchanged:

- `founding-descriptor` selects the actual trial's GN3 chain descriptor.
- `accepted-checkpoint` selects the checkpoint reproduced from the full
  accepted native prefix.
- `accepted-history-index` selects a small public index binding the exact
  replay packet, reproduced history/checkpoint, original public input objects,
  complete compressed pages and separately reviewed bootstrap sources.

The index must identify the financial profile, domain, exact asset IDs, lengths
and SHA256 values. Its declared dependencies cover the complete accepted-data
and auxiliary-source set, including static archive metadata. The existing
static dependencies cover financial profile, native policy/codec, software and
all parameter roles. Every selected asset must be reachable with no cycle or
unselected dependency. This structural check cannot establish current backing.

## Exact replay packet

`kpx8-closed-replay-public-inputs/v1` has exactly:

- `schema`, `financial_profile_sha256`;
- `inputs`: the six names `selection`, `descriptor`, `fetch`, `parameters`,
  `sessions`, `source-pins`, each with `{path,bytes,sha256}`;
- `pages`: `{path,bytes,sha256}` for every main-prefix and post-query-delta
  compressed page, preserving its raw fetch-relative path;
- `expected`: `history_sha256` and `checkpoint_sha256`.

All paths are canonical relative paths under one restored data directory.
Input placement may use `inputs/`; compressed pages retain their exact logical
paths. The root publication selector separately binds each placement to its
explicit producer-public source. The page set must equal both page lists in
the selected fetch object. A missing page cannot mean an empty wallet.

Before publication, the literal audit also examines exact decoded page bytes.
The gzip audit map binds source/path, compressed length/hash and decoded
length/hash. Decoding is bounded per chunk, includes all gzip members and
trailing bytes, and performs no JSON reserialization. Decoded copies are
audit-only objects; the release need not upload them.

## Bootstrap and execution closure

The 63-file archive remains immutable. Newly reviewed recovery replay, public
case-construction, campaign or confirmation helpers are separately selected
public source objects. Every fixed imported helper must have an explicit
authenticated provenance; no original-repository import fallback is allowed.

The selected `replay_closed.py` Source02 authenticates the entire fixed software
inventory and native codec, stages only selected files, then calls unchanged
`replay(...)` in a network-disabled namespace. Crypto, Node, native validator
and SDK paths are explicit. Both decoded selection and replay result must bind
to the fixed financial profile. Exact reproduced history/checkpoint hashes
must match external selection before owner use.

The replay is a recorded validating-node observation. It is not independent
PoW/GHOSTDAG verification or continuously current chain authority. Fresh
acquisition and exact current-head checks are required before each submission.

## Three clients and nine exits

1. Authenticate the complete public closure, runtime and all three whole PKs
   before mounting one original own backup read-only into each fresh owner.
2. Restore and scan accepted round-two history. Derive read-only context from
   the same complete checkpoint and use the fixed typed exit-ready response.
3. Construct quotes/cases and run native validation using downloaded helpers
   inside the closed public namespace. The owner alone produces its Exit proof.
4. Confirm and independently replay each accepted exit before another current
   head is used. Owner order is round-robin; skip only an authenticated typed
   empty result for that same full history, never a missing-data error.
5. After all nine payouts are confirmed, freshly restore original seeds and
   scan complete terminal history. The unchanged SOURCE04 scan requires all
   owned claims spent and rederives historical native payout keys at reserve0.

Only neutral aggregate evidence belongs in the shared release. Per-client
restore/scan/READY exports, participant-to-NF/payout associations, private maps,
CM-position ownership, backup contents/hashes and raw private logs are excluded.
Public protocol history, sessions, commitments, append indices and accepted
transaction bodies remain necessary public evidence.
