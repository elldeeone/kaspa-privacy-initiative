## Source-grounded implementation obligations

These are adaptations to the selected local relation, not claims that upstream implements KPX4:

1. Compact2 and wide32 require their own finalized matrices, PKs and VKs. Bind all ordered CMs and complete Auth528 SHA256 as **two exact LE128 public inputs**; check all outputs, late slots, ordering, reserved bytes and mode. Keep the existing real positioned NF identical across compact, wide and REVEAL; role-tagging that NF would permit one spend per role. Both native sequential NF transitions remain mandatory.
2. Sparse appends preserve `start+i`, cursor and canonical empty gaps. Never rebuild by renumbering discovered receipts. The old-empty subtree claim depends on valid initial state and every accepted transition, not an arbitrary malformed prior root. CM cursor is not receipt/user count.
3. Zero-value continuing outputs retain randomized rho and normal encrypted framing. Terminal R'=0 omission serializes publicly inactive material; a future no-append full exit while R'>0 would reveal a different mode and remains unselected. Existing [dummy visibility analysis](../private-change/observer/DUMMY-VISIBILITY-ADDENDUM-01.md) and frozen observer remain unchanged.
4. Both public VKs are needed for complete public replay; an owner needs only the compact PK to exit. Thirty-two slots are not thirty-two genuine payments or people. Stronger linkage measurement must include common payer lineage, ingress amounts, fees, timing, framing and legitimate side information; arithmetic alternatives are not owner ambiguity or cryptographic feasibility.

## Portability is not retention

[librustzcash parameter loading](https://github.com/zcash/librustzcash/blob/146a08fc779678f6b81997da5f9b7c3378ffccb9/zcash_proofs/src/lib.rs#L110-L136) checks size/hash even for cached files. Adapt content identity and role verification before private witness access. A matching hash proves neither honest setup nor that any independent provider will retain bytes tomorrow. A new randomized Groth16 setup does not reproduce the existing parameter artifact or verifier identity.

A recovery capsule needs the authenticated profile/software identities, both VKs, compact PK when proving, and complete accepted ciphertext/context history with actual sparse positions. Seed/source alone cannot replace missing encrypted receipts. An isolated reinstall using mirrored public bytes demonstrates bounded portability; long-term retention and independently administered providers need separate evidence. Replay must reconcile against fresh validating-node acceptance/current UTXOs before spending. Missing/corrupt history, stale heads and reorgs mean **incomplete/halt**, not zero balance, implicit finality or automatic revealing fallback. [Zcash wallet rewind](https://github.com/zcash/librustzcash/blob/146a08fc779678f6b81997da5f9b7c3378ffccb9/zcash_client_sqlite/src/wallet.rs#L4459-L4516) illustrates reorg-aware tree, transaction and scan-state rollback.
