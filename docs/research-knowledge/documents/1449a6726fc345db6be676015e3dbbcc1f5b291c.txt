# Official Groth16 compression assets for RISC Zero 3.0.3

Checked 2026-10-22 UTC. This file concerns official public compression components only. The authorized native component is downloaded, authenticated and copied task-locally. No compression, proof generation, GPU operation, global installation, image pull or execution of downloaded artifacts has been performed by this research subtask.

## Decisive facts

- SDK release `v3.0.3` is commit `14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6`. Its native CUDA wrapper explicitly requests **rzup component `risc0-groth16` version `0.1.0`**. The SDK crate version and the component version are different version namespaces. [Release](https://github.com/risc0/risc0/releases/tag/v3.0.3), [pinned CUDA wrapper](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/risc0/groth16/src/prove/cuda.rs#L28-L36).
- The component's official signed manifest currently publishes one target agnostic archive. Its RSA-PSS/SHA256 signature was verified locally against the public key embedded in the pinned SDK source, using salt length 32; OpenSSL returned `Verified OK`. The exact manifest, key, signable bytes, signature and verification receipt are retained alongside this file. [Official manifest](https://risc0-artifacts.s3.us-west-2.amazonaws.com/rzup/components/risc0-groth16/distribution_manifest.json), [pinned key](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/rzup/src/distribution/public_key.pem), [manifest verification implementation](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/rzup/src/distribution/s3.rs#L73-L101).
- Native CUDA needs `preprocessed_coeffs.bin`, `fuzzed_msm_results.bin`, `stark_verify_final.zkey` and `stark_verify_graph.bin` at the component root. There is no need to regenerate ceremony material. [Pinned parameter paths](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/risc0/groth16-sys/src/lib.rs#L25-L49).

## Setup provenance and licensing boundary

The pinned SDK's trusted-setup documentation identifies the compressed URL above as the mirror of its STARK-to-SNARK ceremony transcript. Its native component builder downloads that same URL before deriving `fuzzed_msm_results.bin` and `preprocessed_coeffs.bin`; its Dockerfile also pins that URL and checksum. This links the official component build route to RISC Zero's published outer wrapper setup, independently of any application's inner circuit key. [Pinned ceremony documentation](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/website/api/trusted-setup-ceremony.md#L24-L31), [pinned component builder](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/xtask/src/setup_groth16.rs#L39-L49), [derived component preprocessing](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/xtask/src/setup_groth16.rs#L87-L88).

RISC Zero describes a ceremony coordinated with PSE, publishes a [ceremony page](https://ceremony.pse.dev/projects/RISC%20Zero%20STARK-to-SNARK%20Prover), and documents circuit/transcript/contributor-attestation checks. This task authenticated distribution metadata; it did **not** independently verify that transcript or contributor attestations, prove that setup secrets were destroyed, or audit the wrapper circuit. The repository's local `run_ceremony.sh` explicitly uses a pretend contribution; that script was not run and is not evidence about the published ceremony. [Pinned ceremony description](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/website/api/trusted-setup-ceremony.md#L33-L55), [local example ceremony script](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/groth16_proof/scripts/run_ceremony.sh#L18-L22).

The pinned repository uses Apache License 2.0, and the inspected Rust sources carry Apache-2.0 headers. Neither the signed manifest nor the four-file archive provides a separate parameter-artifact license; no broader licensing claim is made from that metadata alone. [Pinned repository LICENSE](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/LICENSE).

## Official timing and resource evidence

RISC Zero's immutable benchmark snapshot at ghpages commit `0f43ffca39a92660d9c21fc916f4f0146669d923` records SDK commit `14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6`, exactly matching `v3.0.3`. The matching RTX 4090 JSON and SDK identity marker are retained alongside this file. [Official benchmark identity](https://raw.githubusercontent.com/risc0/ghpages/0f43ffca39a92660d9c21fc916f4f0146669d923/dev/datasheet/COMMIT_HASH.txt), [official RTX 4090 benchmark JSON](https://raw.githubusercontent.com/risc0/ghpages/0f43ffca39a92660d9c21fc916f4f0146669d923/dev/datasheet/Linux-nvidia_rtx_4090.json).

| Exact-version RTX 4090 row | Recorded duration | Meaning |
| --- | --- | --- |
| `shrink_wrap` | `3,995,798,310` ns (3.996 seconds) | Final compression of a prepared `identity_p254` receipt, including native witness calculation. Its 262,144 cycle field is the fixed recursion circuit size. |
| `groth16` | `3,719,050,884` ns (3.719 seconds) | Separate end-to-end LOOP_ELF execution, proving and compression run, with 65,536 loop iterations and 262,144 reported guest cycles. |

These rows are separate runs and must not be added as consecutive stages or extrapolated into an RTX 3070 time estimate. [Pinned benchmark implementation](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/risc0/zkvm/examples/datasheet.rs#L423-L490).

The `shrink_wrap` row explicitly writes `ram: 0`, meaning unmeasured. The end-to-end `groth16` row records `2,381,942,084` bytes through the RISC Zero HAL allocation tracker. Native Groth16 separately calls C++ `gpu.Dmalloc`, so that metric cannot establish total process RAM or peak VRAM and cannot prove 8 GB GPU compatibility. Exact SDK 3.0.3 Groth16 peak RAM and VRAM remain unknown. [Pinned benchmark metric](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/risc0/zkvm/examples/datasheet.rs#L448), [HAL tracker](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/risc0/zkp/src/hal/cuda.rs#L240), [native allocations](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/risc0/groth16-sys/kernels/cuda/groth16_prover.cuh#L233).

CUDA kernel builds default to `-arch=native` unless `NVCC_PREPEND_FLAGS` or `NVCC_APPEND_FLAGS` is supplied; pinned CI uses `sm_89` on an RTX 4000 Ada. No official exact-version sm86 minimum, RTX 3070 fit guarantee, or CPU/Docker timing was found. Docker's 16 MiB stack setting is not a RAM requirement. General zkVM segment-size guidance also does not establish Groth16 compression requirements. [Kernel build logic](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/risc0/build_kernel/src/lib.rs#L142), [pinned CI](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/.github/workflows/main.yml#L230), [general local proving guidance](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/website/api/generating-proofs/local-proving.md#L20).
