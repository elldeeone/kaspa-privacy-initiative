# Continuing offline S7: public replay and owner scanning

**The existing wallet already identifies claims by their global commitment position. Preserve that behavior.** The minimal new seam is a separate S7 public transaction decoder/replayer exposing ordered `(position, CM, ciphertext)` records from ordinary and paired branches. Keep the old v6 parser, current one-shot state assertion and their immutable evidence unchanged.

This is a source/design note for review, not implementation or permission to generate parameters/proofs. It follows `binding/research/intensive-2026-10-22/OFFLINE-PAIRED-OWNER-LIFECYCLE-FEASIBILITY.md`. The proposed continuing profile is a new public `DO_NOT_FUND` instance; no existing reserve, key/domain, guest/image, J42/J336 or one-shot policy is upgraded.

A shared lower-level public transition routine can retain ordinary rules while preserving paired multiplicity.

## Position identity and duplicate records

The present scanner pushes one `Owned` entry per successfully decrypted position; it has no CM-keyed dedup map (`wallet.rs:305–318`). NF derivation includes the actual position (`:313`), selection's `HashSet` contains positions only (`:386–396`), and membership paths use that same position. The existing source test `equal_commitments_at_different_positions_have_independent_spentness` (`wallet/tests.rs:702–762`) covers equal CM/opening at positions3/5, spending one and keeping the other selectable. It is an unproved scanner fixture; it does not test identical raw ciphertext bytes or the future paired branch.

For P, iterate all four 217-byte `(CM32 || ciphertext185)` entries in their published raw-byte lexicographic order. Assign positions `prior_n + slot` before trial decryption. Equal records must yield two entries at different positions, not one cached claim. Sorting ties reveal no unique inner-bundle origin and need none. Never re-sort CMs separately, pair ciphertexts by a CM lookup, or use CM/ciphertext/hash as a claim key.

The simplest first implementation retains full scanning and no new persistent cache. If a later cache is needed, its identity must include the authenticated pool/descriptor and global position, with exact record consistency and head/reorg invalidation. A repeated position within one selected spend is invalid; identical records at different positions remain separate value-conserving claims with different real NFs.

## Minimal public replay contract

1. **Separate profile and exact framing.** The source plan proposes `KPI2LCT1 || u16LE(1) || branch`, ordinary5231 bytes and paired1204 bytes. Freeze these in the ADR before coding. Reject other selectors, wrong lengths, mixed layouts and trailing bytes. Ordinary decoding yields the existing auth377, two ciphertexts, nextS7 and witness; paired decoding yields complete P1088 and nextS7. The old `replay::bundle` is intentionally v6-only (`replay.rs:185–205`) and must remain so. Expose one branch-neutral iterator of complete public output records plus their source offsets/global positions.
2. **Reconstruct public state independently.** Replay from the authenticated founding CM and sentinel NF tree. Ordinary bootstrap/ADMIT/SPEND adds two CM leaves and a history root; DRAIN adds no CM/history. For P, check four distinct nonzero NFs, preserve P rawlex order while indexed-set comparisons remain unsigned little-endian, insert all four sequentially, and append all four records sequentially. Append `(n+2, root_after_two)` then `(n+4, root_after_four)`. Maintain `roots.len() == (CM_count+1)/2`, with final root equality. Compare all nextS7 fields to the body, not just a digest.
3. **Do not require hidden A/Q.** The paired public body exposes P, not the inner authorizations/bundles/permutation witness. `StateGate.evaluate` reads the common anchor/count from hidden input after P (`common/src/lib.rs:164–175`), so it cannot be called using public P alone. Public reconstruction can reproduce NF/CM/history updates, but cannot independently reverify hidden ownership/conservation/anchor membership. Those claims require the fixed new outer proof and exact native context. Retain separate results for public-state reconstruction, native proof/context verification and chain acceptance. No inferred private input/group attribution belongs in public replay.
4. **Authenticate the whole native body.** Build the exact claim from the actual consumed outpoint, actual S7/redeem, P, successor S7 and integer reserve/fee. Verify complete immutable body continuity containing both ordinary and paired branches. A paired spend has exactly its permitted reserve input and positive successor, `R' = R - aggregate_fee`, with no redirected/extra payout. Ordinary ADMIT retains its exact funding outpoint, amount/script and native signature checks; DRAIN binds the actual owner payout and continuing/terminal output shape. Compare canonical transaction bodies/IDs/full hashes and run native Full with supplied predecessor UTXOs. Matching roots or a valid receipt in isolation is insufficient.

The pair's `n+2` history leaf is an authenticated **CM prefix**, not a separately accepted transaction, reserve UTXO or intermediate full S7/NF state. A later proof may use an included CM-prefix anchor while checking spentness against the current NF root. Do not invent an intermediate accepted reserve spend at that count.

## Genesis, acceptance and owner recovery boundaries

A new descriptor must independently pin fresh domain, poolID, inner VK, outer image/key/profile and complete immutable body. Prefix poolID is not the inner authorization domain. Genesis must reconstruct n1/m0, initial CM, sentinel-only NF root and history(count1); an arbitrary well-shaped S7 declaration is not initialized backing. The current one-shot `State::check` rejects m<2 (`two-v6-state/common/src/lib.rs:101–104`); do not apply it globally to genesis. The ordinary bootstrap proof must consume the unique founder claim and bind `bootstrap == actual reserve`. ADMIT/pair require a completed valid bootstrap; retain the existing owner-authorized founder DRAIN semantics without a rescue key.

Existing `Context::new` binds supplied head count/full hash and replays native transactions (`wallet.rs:248–279`). It does not authenticate chain acceptance. Existing parent lookup validates body identity/output shape but does not recursively validate unknown funding ancestry (`replay.rs:119–181`). The proposed offline lifecycle must explicitly assume only its declared public test seed UTXOs, verify generated funding transactions and descendants against those exact supplied predecessors, and keep chain acceptance false. A later live adapter would need an authenticated accepted view and reorg handling. Missing prefix/body/receipt data must not be filled from a proposer state cache.

Each owner receives only their own publicly labeled test backup, complete public history (including the public compressed outer proof in the paired transaction), fresh hash-pinned public PK/VK, and the owner/native software. They need no hidden A/Q, permutation/group assignment, separate host RISC0 receipt artifact, outer prover executable or collector. Restore by scan, derive position NFs, rebuild current paths, generate their ordinary owner proof and enforce their destination. Retain the fresh public PK until both exits complete. The old discarded-PK fixture cannot satisfy this lifecycle. If public history/PK is unavailable, liveness stops; no fallback withdrawal authority is introduced.

Then prove each payout is spendable using that owner's derived native key. Test reverse owner ordering against a separately rebuilt current context, not by combining conflicting spends.
