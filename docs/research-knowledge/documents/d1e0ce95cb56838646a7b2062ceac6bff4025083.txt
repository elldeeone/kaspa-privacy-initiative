# Isolated CLI source-loss control

Frozen before execution. This one additional integration question uses the real
HTTP retrieval CLI in a separate filesystem/PID/user namespace. Its literal
loopback network is shared only with its public-fixture controller servers.

Create fake public structural CAS files, byte-copy them to a fallback directory,
start both local sources, stop the preferred source, and delete ONLY the owned
original fake-source/cache directories. Mount only the trusted public selection,
two production source files, ordinary system/CAs and an empty client output.
Do not mount either mirror filesystem, test fixture source or original source/
cache. The fresh client fetches the root index and all five objects through HTTP
fallback and stages the exact selected fake parameter bytes. A pre-entrypoint
probe records only whether original source/cache paths are absent.

Success means artifact retrieval/material staging after bounded local source
loss. It is not actual Ark parameter decoding, private wallet recognition,
accepted chain/current state, proof/native exit, independent providers or long-
term retention. All bytes are explicit PUBLIC_STRUCTURE_ONLY_DO_NOT_FUND fixtures.
Do not add a proof/key/currentness success claim. Original real caches/backups/
releases are never mounted or mutated. Retain any failing result; do not retune
its expected outcome. Prior control counts are not summed as extra outcomes.
