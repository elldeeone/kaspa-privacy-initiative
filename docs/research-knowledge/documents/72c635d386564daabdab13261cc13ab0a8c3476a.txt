The Full lock has 428 package entries: the local package, 21 packages from public `kaspanet/rusty-kaspa` revision `01b532e8b553523216471682649693af92f0fd16`, and 406 registry entries. It has no path dependency or private Git source. The copied policy predicates are explicitly source-adapted from native Kaspa. Its exact upstream license is **ISC, copyright 2022–2024 Kaspa developers**; the closed helper has no local NOTICE. Add an explicit publication-side attribution/license copy for that pinned upstream rather than altering the frozen Rust source or manifest. [Pinned native license](https://github.com/kaspanet/rusty-kaspa/blob/01b532e8b553523216471682649693af92f0fd16/LICENSE), [pinned policy source](https://github.com/kaspanet/rusty-kaspa/blob/01b532e8b553523216471682649693af92f0fd16/mining/src/mempool/check_transaction_standard.rs).

The extractor lock has 238 entries: its local package and 237 registry entries, no Git or path dependency. Its existing `NOTICE` preserves the vProgs ISC permission/disclaimer and 2022–2026 copyright for the adapted witness/key/point mappings. Retain it with the source. Direct dependencies pin SDK `risc0-zkvm = 3.0.3`, verifier components `3.0.4`, recursion `4.0.4` and Arkworks `0.6.0`; do not normalize these versions after the fact. The relevant RISC0 SDK license is Apache-2.0. [Pinned vProgs license](https://github.com/kaspanet/vprogs/blob/f9b84a863a7c7c20586a9cf947550475e894f72e/LICENSE), [SDK release source license](https://github.com/risc0/risc0/blob/14b5d588dd01cf4f7ba804d8bb0a61264e6ae2c6/LICENSE).

The executable redistribution assessment is **incomplete**, and neither existing packet supplies a complete linked dependency notice bundle:

- Native executable read-only `nm -C` inspection finds 30,645 `rocksdb::` symbols. Its locked native dependencies include RocksDB/LevelDB/Snappy, Zstd and secp256k1 code with additional Apache/MIT/BSD attribution material; root Apache text alone does not inventory these notices.
- `kaspa-math` locks `malachite-base` and `malachite-nz` 0.9.2, each declaring `LGPL-3.0-only`. No matching demangled symbol was found in this executable. **Lock presence is not evidence of actual linkage**, and the audit does not infer a copyleft obligation from it. Actual retained objects and applicable redistribution terms need resolving before distributing this binary. Similarly, do not infer a GPL/AGPL requirement merely from unrelated or alternative-license files in the vendored RocksDB source tree.
- The extractor links RISC0/Arkworks and other registry code. Its vProgs NOTICE does not inventory all third-party binary notices. The lock-level source inventory includes MIT, BSD-3-Clause, Zlib and Unicode license expressions as well as Apache alternatives. Some lock entries are target-specific, procedural macros or build dependencies; a lock inventory is a conservative superset, not the set of linked code.
- Published crate metadata was inspected from the existing local cache, without installation. Five registry entries in each lock were absent locally (`jiff-static 0.2.38`, `jiff-tzdb 0.1.9`, `jiff-tzdb-platform 0.1.3`, `portable-atomic 1.14.0`, `portable-atomic-util 0.2.8`). No complete binary-notice attestation can be made from this cache-only check.

These are reasons to select source/artifacts separately now, not reasons to replace dependencies, strip a historical executable, rewrite a frozen manifest, or retune a result. If a source/vendor archive or executable is later selected for release, assemble its exact third-party notices and any applicable source/relinking materials as a separate reviewed package. No SDK/toolchain/prover binaries or downloaded compression assets belong in this source publication selection.

## Public-material and portability checks

All 65 files were checked for credential/private-key filename patterns and bounded common credential/PEM token shapes, including the two executables without executing them. No match was found. The manifest allowlists contain no wallet seed, signing key, proving key, evaluation dataset, cloud credential file or private input directory. The 424-byte key is the pinned **public verification key**; the proof/seal, J336, roots, amounts, outpoint, declared synthetic UTXO and transaction are intentionally public research artifacts. This is a bounded inventory/content check, not a general secret-detection guarantee.

No `include_bytes!`, `include_str!`, `include!`, compile-time environment path, private crate path or external runtime asset dependency was found in these helper sources. The source trees and locks can be built against public upstream sources; the closed executable is not required for that. The evidence logs deliberately retain historical `/home/luke/...` paths. Those paths are provenance, not portable commands or a dependency on private contents. Select fresh output directories for any later repetition, and preserve the exact expected tuple and inputs.

The retained builds used an existing dependency cache, ordinary OS/C++ tooling and offline Cargo. This audit does not claim that a cache-free build was reproduced or that Cargo.lock alone reproduces identical binary bytes; toolchain, target, native compiler and environment also matter. No rebuild, proof generation, native VM run, network/funded action or blocked owner/recovery workflow occurred in this audit.
