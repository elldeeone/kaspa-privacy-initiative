# Public recovery transport implementation

Base: `5aaf99532d8714e510d421102df719f60f54d073`. This extends ADR0057's
publication recipe, without changing the financial instance, capsule authority,
native program, proving relation or currentness rules. Existing packages and
sealed evidence remain unchanged.

1. Prepare an explicit public development-parameter generation: selected compact
   manifest, genuine public PK as fixed1GiB raw chunks, chunk index, NOTICE,
   exact public software inventory and offline/CAS objects. Classify it
   `DEVELOPMENT_PARAMETERS_DO_NOT_FUND`. Exclude backups, witnesses, private
   controller records, owner maps and main unbroadcast Auth/history.
2. Supply whole-object length/SHA and the parameter manifest identity from
   independently authenticated installed selection. A publication index, TLS
   endpoint, filename or self-consistent mirror never supplies that authority.
3. Download with verified system TLS, exact selected hosts, HTTPS-only bounded
   redirects, no credentials/cookies/proxies, identity encoding and bounded
   streaming. Signed redirect URLs/queries never enter receipts. Verify every
   chunk and the complete raw object before atomic no-clobber handoff. The
   existing loader must authenticate its complete owned PK/VK/dimensions again
   before private input. Transport never executes downloaded software.
4. Prepare GitHub release assets, ordinary HTTPS CAS layout and an offline tree.
   Root reviews the exact public asset list before any upload. Separately
   controlled providers/retention are inventoried only when evidenced; two
   GitHub endpoints or two local directories are not independent providers.
5. Test missing issuer/cache, corrupt/missing/reordered data, wrong external
   authority, TLS/redirect policy and inode aliases using public synthetic
   fixtures. Exercise real public HTTPS bytes separately. Genuine compactPK
   preparation is root-authorized at at most2CPU/3GiB/swap0; no proof/backup or
   current-node request is part of this lane.

The offline output recovers public material, not current spendability. New KPX4
development history has no accepted-current bridge in the old KPX3 network
client. An intact package cannot supply that missing evidence or imply zero
balance. Full cold software restoration is a separate externally pinned wallet
inventory; the adapter copies its exact bytes without choosing or launching code.

No separately administered mirror was found in the initial authorized account
inventory. Root is asking the owner for an existing independent operator/access.
That requirement stays open while preparation and HTTPS verification proceed.
