# Public orchestration adversarial pass

Reviewed the fixed source set and its selected-SDK integration correction. The independent
reviewer separately found and calibrated the public-open race and exact SDK
intent join; both fixes have retained regression controls.

- **Inflation and unauthorized reserve release:** the journal reducer cannot
  establish acceptance. Only fixed complete Full-page/body/context verification,
  fresh NativeFull and selected financial replay can reach accepted recording.
  A caller-provided true flag or arithmetic-only result is insufficient.
- **Double spending:** immutable exclusive intents prevent this runner from
  sending a used stage twice, including after an uncertain response. Fresh exact
  input queries reject missing or changed sources. Chain consensus remains the
  double-spend authority; a local file journal creates no consensus guarantee.
- **Changed bytes:** own submission joins the complete SDK body/context to the
  retained native case, including unsigned budgets/witnesses and exact u64
  values. Accepted recovery instead validates actual bytes and all financial
  semantics, permitting valid same-ID variants without changing the intent.
- **Privacy:** public transaction bodies, proofs and digests remain observable.
  Stdout carries status/counts and transaction identifiers. No owner label,
  private path, backup-derived claim mapping or raw private worker log is
  exported by these entry points. This does not repair construction linkage or
  establish financial privacy.
- **Dependency loss:** a cold owner has a standalone send attempt and accepted
  replay path without a coordinator journal. Missing parameters/prover/software
  can halt preparation; no admin recovery or alternate withdrawal authority is
  introduced. Durable independent public-history availability remains a
  separate system requirement.
- **Stale state and reorg:** accepted replay checks complete retained pages and
  current node observations. Already recorded financial predecessors must match
  a later accepted prefix. An immediate exact-input query is mandatory before
  submission. Remote observations remain non-atomic and can become stale after
  the query; the selected validating chain still decides acceptance.
- **Host and file trust:** source and generic assets are externally selected,
  read-only and trusted immutable during execution; system Python/OS libraries
  and the host remain premises. Caller chain pages are checked against all four
  backup identities before opening, then copied read-only. Opened inode checks
  precede the first byte in public readers. A malicious host is out of scope.

The initial source freeze01 had an integration gap: historical SDK helpers
assumed owner-namespace remapping, while public orchestration runs outside
that namespace. Source freeze02 replaces the public roundtrip with a fixed
roundtrip-only adapter and passes explicitly staged SDK bytes to the accepted
Full-page verifier. The owner namespace default remains a separate valid path.

Public controls used synthetic sentinels and mocked replay, plus an actual SDK
roundtrip with an unsigned public synthetic transaction. No real backup,
genuine proof, Native execution or live network submission was performed in
this lane. A complete four-payout rehearsal is still required.
