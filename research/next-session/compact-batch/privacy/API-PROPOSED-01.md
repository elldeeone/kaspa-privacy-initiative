# Linkage observer API proposal

No heldout input is generated by this document. It is a strict schema proposal,
not an executed observer or a native protocol wire format.

Observer stdin is one JSON object with exactly these root fields:

```text
schema = kpx3-payment-linkage-public/v1
classification = PUBLIC_SYNTHETIC_DO_NOT_FUND_ARITHMETIC_MODEL
known_wallet_policy = one_real_full_cashout_wide_positive_varied_future_wallet
profile = C | C+1 | C+8
rate_sompi_per_mass = 100
exit_credit_sompi = public integer fee credit (not economic principal)
domain_hex32 = dedicated disposable model domain
funding_directory = [{source_id, payer_role}]
participant_roles = [] | [2] | [2,3,4,5,6,7,8,9]
participant_records = [{participant_role, position, cm, value_sompi,
                        original_nf, invoice_counterparty_role}]
events = [strict public event objects]
```

There is no seed, truth path, target eligibility mask, label/output-role map,
private intent, selected input position or hidden owner/funding-source map.
A participant record is a specifically allowed own-receipt fact; it is not a
free-form channel for the generator to supply unrelated truth. Invoice
counterparty roles must be a declared payer role or null. Matching a role in
the public funding directory never adds original-funding-lineage equality. Main
heldout participant views include the legitimate authenticated business
counterparty; null is only an explicitly weaker control.

Each event contains exactly:

```text
ordinal, tx_id, minute, kind,
prior_reserve_sompi, reserve_sompi, fee_sompi, payout_sompi,
payout_spk_hex36,
prior_cm_cursor, cm_cursor, prior_nf_count, nf_count,
mode, append_start,
notes = [{position, cm, ciphertext_hex264}],
nfs = [opaque canonical32-byte values],
ingress_value_sompi, ingress_source_id, public_ingress_note_hex168
```

An ingress has mode=null, one appended position at its prior cursor, no NFs or
payout, a canonical public Note168/value/source and reserve addition. Private
mode2/32 has exact aligned sparse append positions and2 fresh nonzero NFs;
mode32 hasP=0. Terminal mode0 hasR=0/P>0, no appended notes, start0 and carried
cursor. Native destinations are null forP=0 and canonical SPK36 forP>0.

All JSON integers reject booleans/floats/negative/overflow values. Hex is lowercase
with exact widths. Duplicate JSON keys, unknown/missing fields, incomplete
prefixes, repeated tx IDs or NFs, bad reserve/count/order/alignment and private
hint fields reject. Repeated CM bytes at different positions remain distinct
liabilities and impose equal value under commitment binding; they disable
symmetry grouping where an exact automorphism is not demonstrated. Alignment
holes never appear as notes or selectable inputs.

Output separates BASELINE_SAT/INCONSISTENT/INCOMPLETE, exact conditional facts,
SAT certificates, UNKNOWNs, ciphertext-format flags and fixed heuristic guesses.
Every model result states one-real-wallet/known-full-cashout assumptions and
missing ownership/cryptographic/consensus constraints. A SAT result is not a
privacy or authorized-history certificate.

Each native event gets exhaustive input-CM and original-source candidate rows.
Every public note gets value forcedness; every private-born note gets all native
cashout candidates plus explicit NONE. A forced positive link requires exactly
one feasible native event and UNSAT for NONE and every other event. Any UNKNOWN
prevents forcedness. Symmetry lifts carry representative/class/permutation
metadata and an independently verified certificate per SAT member.

The independent Python integer certificate consists only of public positions,
integer note values and selected input per public private event. It recomputes
all conservation, current unspent values, lineages, participant facts, sparse
counts and at-most-once use; it trusts no solver-reported validity Boolean.
Certificates can include an arithmetic alternative assignment, not its
hypothetical secret keys, hash openings or valid proof.

A scorer is a separate process with exact public input, sealed observer output
and disposable model label truth only after the global96-prediction barrier.
It never invokes the observer, fits an attack, selects a favorable case or reads
generator keys/seeds. All source inputs must be pinned before heldout execution.

Constructive search accepts only public ledger data. Successful SAT certificates
are checked against an explicit typed query; failed/bounded search falls back to
SMT and never means UNSAT. COMPLETE predictions independently require every
public note/native event/candidate/source/NONE/value row exactly once, no UNKNOWN
rows, consistent duplicated projections and recomputed forced fields. A valid
global certificate cannot be reused to certify an unrelated requested predicate.

Native SPK bytes are retained exactly. Current wallet payout derivation is
claim-specific KPX3PAY HMAC, not one key per backup. The sampler's independent
valid payout keys are an explicitly declared PRF-output abstraction; same-SPK
endpoint clusters are public if present, without inferring humans or CM lineage.

The primary16 policy tag is VARIED_POSITIVE_FUTURE_WALLET: one real input,
full-native zero private outputs, and all32 wide outputs positive; individual
values vary prospectively. It is not the current uniform-value financial demo.
A fixed PUBLIC_CURRENT_UNIFORM32 control uses policy tag
one_real_full_cashout_wide_positive_equal_current_demo and explicitly equates
all32 values in every wide action, making its amounts forced. The legacy tag
one_real_input_full_native_cashout remains accepted only for retained old public
development fixtures and imposes no all-positive/equal wide prior.

Current payout policy is bound to poc/compact-batch-lifecycle/actions.py, SHA256
a1b725e026dc7403bbe4a3d6c1f713bf48d4e67ecdbed67facda7d6098658484.
Its claim-specific key derivation is modeled by independent valid PRF-like
payout keys, not by running the wallet's HMAC or proving backup recovery.

The first solver UNKNOWN stops queries in that view only. Every other fixed
view still runs, and all96 complete/incomplete predictions are durably sealed
before truth scoring. Solver memory exhaustion is UNKNOWN, never UNSAT.
