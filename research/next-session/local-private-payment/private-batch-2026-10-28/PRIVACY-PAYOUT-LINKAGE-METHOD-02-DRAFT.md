# Paired native payout linkage experiment, version 02

**DRAFT — no actual candidate keys, views, results or scoring are authorized by
this file.** Freeze a separate immutable copy and its exact execution selection
before generation. Artifact/catalog and source bindings remain pending.

This experiment measures a bounded address and transport linkage improvement.
It does not change the old frozen H1, thresholds, workload or retained failure.
The current transfer format already has no public pair tag. That earlier pair
tag counterexample is a control, not a current wire-format finding.

## Concrete question

The current Invoice208 gives a legitimate sender `native_pk`. The old wallet
constructs and authorizes an exit paying that same key. Can independently chosen,
owner-authorized fresh payout destinations increase compatible honest terminal
matches, after retaining every other legitimate public, economic and colluder
fact?

Existing native/AuthExit authorization can bind an arbitrary exact destination.
The implementation must retain owner AK authorization over the entire exact
Exit. Redirecting a destination, amount, fee, action, context or domain after
authorization must fail. No new circuit, proving key or cryptographic profile is
part of this experiment.

5. Genuine source-executed and verified public proof artifacts are required.
   Public known-seed fixtures remain controls, not actual-wallet evidence.

## Exact views

**Contact/public-terminal view:** the actual legitimate sender/colluder contact
invoice, its constructed receipt (`rho`, value, CM), its own known receipts and
payouts, the declared public workload/economic facts, and complete public native
proof/terminal data. Honest private plans, invoice secrets and fresh payout keys
are not supplied. Do not publish full Invoice208 as a global catalog: its
domain-stable delivery key and native key are recipient identifiers.

**Dispatcher view:** the complete actual observed argv, mount, traffic and output
routes, including the existing owner-labelled `exit_release` clear candidate
path. Its owner-to-new-payout relation is a required fact. Fresh payout keys alone
must not be reported as fixing dispatcher privacy.

**Union:** all facts in both views, plus the declared corrupt participant's
legitimate facts. Missing or unmodeled full corrupt-server/terminal data prevents
an overall privacy qualification. A gain in the narrower contact view cannot be
promoted to a union or cryptographic privacy claim.

Before/after capture roots must contain actual executed artifacts. A redacted
copy, renamed route field or omitted input channel is not an after mitigation.
Common/anonymous native submission is a separate candidate until its real path
and observed traffic exist; its absence remains a recorded limitation.

## Public statement facts to retain

Retain the complete native prefix and Exit BODY1604: context/roots/counts/reserve,
opaque action, updated NF state, remaining value, fee, payout, destination SPK,
spent NF and indexed-NF update witness. Preserve public history, timing and route
correlation. The final proof has ONE plus two digest instances; opaque proof bytes
remain outside this bounded model.

The public Exit does not expose spent CM, receipt hash/index, AK/ASPI or the
original native key. A sender knows the receipt it constructed and its CM, but
cannot compute an honest recipient's NF without that recipient's `nk`. This does
not authorize dropping any other actual computable identifier.

## Criteria and stop rules

- The exact baseline invoice-native-key lookup must succeed on genuine selected
  baseline artifacts, or record a falsified premise / unqualified baseline.
- A contact-view improvement requires a strict increase in actual compatible
  honest matches, with the true assignments retained, under unchanged frozen
  economic/timing/contact facts. Lookup disappearance alone is insufficient.
- If remaining facts still select one honest match, report **no measured gain**.
  Excluding the true edge is an invalid observer model, not a pass.
- With the current owner-labelled release route, dispatcher/union linkage is
  expected to remain collapsed. Report that failure even if contact-view matching
  improves. Retain the old H1 failure without retuning or omitting colluder facts.
- Missing genuine proof provenance, exact owner authorization, complete required
  views, source bindings or pre-truth prediction seals yields **UNQUALIFIED**.
- Preserve every negative. No actual private Original/controller/truth body is
  read or hashed by the Root/controller. Only closed roles process permitted
  private inputs; outward results contain typed public counts/commitments.
