# Official relay-fee and estimate units — 2026-10-25

**The checked official default is 100 sompi per gram of relay mass, not 1.** The configuration stores **100,000 sompi per 1,000 grams**. Thus a computed relay mass of 192,284 requires 19,228,400 sompi under that default; there is no further division by 1,000 after converting the configured rate to 100 sompi/gram. This is a source-derived policy result, not transaction admission or settlement evidence. [Selected release configuration](https://github.com/kaspanet/rusty-kaspa/blob/01b532e8b553523216471682649693af92f0fd16/mining/src/mempool/config.rs#L17-L20), [selected relay calculation](https://github.com/kaspanet/rusty-kaspa/blob/01b532e8b553523216471682649693af92f0fd16/mining/src/mempool/check_transaction_standard.rs#L67-L104).

| Quantity | Exact meaning in the checked official code |
| --- | --- |
| Relay-rate configuration | Unsigned 64-bit100,000 sompi/kg; kg here means 1,000 mass grams, not bytes. |
| Relay mass | `max(compute_mass, normalized_transient_mass)`; storage is excluded from this floor. |

| Relay fee | Saturating u64 multiplication of mass by configured sompi/kg, integer division by 1,000 (floor), fallback to the configured rate if the result is zero, then cap at MAX_SOMPI. At the default and ordinary valid mass this is exactly 100×mass. |

**Relay admission and inclusion-rate estimates use different denominators.** The official mempool's ranking key includes normalized persistent storage as well as compute and transient mass, then calculates fee divided by that mass. Therefore multiplying a recommended rate by all-three-dimensional normalized mass can exceed the relay floor when storage dominates. It must be described as an inclusion/ranking policy, not confused with the minimum relay check. [Ranking mass](https://github.com/kaspanet/rusty-kaspa/blob/4edcbbccb449f84832afb1ca157904b35f37d006/mining/src/mempool/model/frontier/feerate_key.rs#L23-L35), [all-three-dimension construction](https://github.com/kaspanet/rusty-kaspa/blob/4edcbbccb449f84832afb1ca157904b35f37d006/mining/src/mempool/model/frontier/feerate_key.rs#L87-L100).

RPC `getFeeEstimate` bucket `feerate` values are floating-point **sompi/gram**, already converted from the integer sompi/kg configuration. They are estimates for inclusion time, not integer sompi transaction fees or chain-acceptance promises. The manager passes the configured minimum converted by division by 1,000 into the estimator; the estimator bounds its recommendations by that supplied minimum. A returned 100 is 100 sompi/gram; dividing it by 1,000 again would underprice the default by 1,000×. [RPC model and units](https://github.com/kaspanet/rusty-kaspa/blob/4edcbbccb449f84832afb1ca157904b35f37d006/rpc/core/src/model/feerate_estimate.rs#L5-L34), [configuration conversion](https://github.com/kaspanet/rusty-kaspa/blob/4edcbbccb449f84832afb1ca157904b35f37d006/mining/src/mempool/config.rs#L137-L141), [manager call](https://github.com/kaspanet/rusty-kaspa/blob/4edcbbccb449f84832afb1ca157904b35f37d006/mining/src/manager.rs#L220-L241), [estimator bounds](https://github.com/kaspanet/rusty-kaspa/blob/4edcbbccb449f84832afb1ca157904b35f37d006/mining/src/feerate/mod.rs#L140-L162).

The specific 100-sompi relay-floor check is **standardness policy**, not a universal chain fee threshold: the official mempool invokes it only when `accept_non_standard` is false. Enabling that flag skips this standardness check, while other limits, double-spend and replacement checks still apply; it does not establish that a public peer or miner will accept a below-default transaction. Replacement-by-fee constraints are obtained and enforced separately from standardness. [Standardness gating](https://github.com/kaspanet/rusty-kaspa/blob/4edcbbccb449f84832afb1ca157904b35f37d006/mining/src/mempool/validate_and_insert_transaction.rs#L157-L168), [separate RBF and post-validation flow](https://github.com/kaspanet/rusty-kaspa/blob/4edcbbccb449f84832afb1ca157904b35f37d006/mining/src/mempool/validate_and_insert_transaction.rs#L20-L38), [context checks](https://github.com/kaspanet/rusty-kaspa/blob/4edcbbccb449f84832afb1ca157904b35f37d006/mining/src/mempool/validate_and_insert_transaction.rs#L75-L82).

Any live qualification must record Tor-only transport, peer/network/version/time, raw RPC units and the exact transaction masses; actual submission and confirmation remain separate evidence.
