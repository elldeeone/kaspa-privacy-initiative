Status: frozen question before execution; actual known pilot, not blind scoring.
Baseline: `63f494053b743ac9bfbd2d1842f69e0f806ef8e3`.

## Inputs, targets and observer

The exporter reads exactly six public accepted-node observation excerpts from
the completed fresh TN10 pilot. It exports canonical accepted bodies, populated
public input contexts, accepting headers and order under ordinal identifiers.
Researcher stage/owner filenames remain in a separate source map which is not
mounted in the attacker process. No identity/profile, backup, seed, invoice,
private witness, expected-payment map or local truth file is an attacker input.
The earlier published pilot is already known to researchers; this is expressly
not held-out statistical evidence. Original accepted-node trust remains.

C targets the two public PRIVATE output slots, identified only by position,
commitment and creating transaction. Before reveal, report a necessary arithmetic
outer relaxation over the two publicly admitted note values, one/two-real input
possibilities, fixed two-output padding and the unchanged 60M positive floor.
This is not proof that alternate cryptographic witnesses exist and it assigns
no probabilities. In particular, two public NF insertions do not reveal arity.

After cashout, recompute each public Note168 CM, K and original positioned HMAC
NF, then match CM **and position** to PRIVATE outputs and exact public P2PK payout.
Predict two forced note-value and output-to-payout links. Known direct-note
pilot semantics make these historical received payment values, but the observer
must not infer that every arbitrary private output is a payment rather than change.
No human identity, C+P, C+P+A, infrastructure, ciphertext confidentiality or
representative-population claim is scored.

## Prospective controls and outcome rule

Before the actual input run, cheap synthetic malformed controls must reject
CM/key/NF/position/value/payout and extra actor-metadata corruption. They are
byte-level controls, not accepted native transactions. An empty/unsupported
transcript is incomplete, never privacy. The actual run occurs once after
independent source/input/freeze ACK, without keys, RPC, native execution, GPU or
proving. Use one CPU, 2 GiB operational memory allowance, network isolated, only
script+public input read-only and a fresh output writable. Retain the exact
source/input/runtime hashes, result, measurements and cleanup.

The result can falsify confidentiality of the selected revealed output-note
values and links. It cannot qualify RFC-0012's 32 roles/eight adversaries,
10% identity, 20% amount, five-point advantage, selective-precision or zero
forced-disclosure gates. The previous `21103/100025 = 21.09772557%` common-price
prior failure remains failed. No case, gate or workload is retuned.

fresh payout script in the proof statement. Binding the payout to note.nativePK
