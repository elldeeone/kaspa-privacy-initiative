# Independent payments: targeted source refresh

**Finding:** plain aggregation of the current action proofs cannot remove their public payer/output grouping. The viable established design family to compare is **separate owner-local spend authorization and output construction with transaction-level value balance**, rather than one publicly identified payer cohort per action. Sapling/Orchard and MWEB provide component precedents; none is a drop-in owner-witness-private multiparty implementation for the current SHA-note/Groth16/native policy. Capacity exits can be addressed separately with a proof-constrained no-append full-claim mode and reserved spentness capacity; a future tree rollover must retain old claims and spentness.

These are scoped observations, not cryptographic owner identification. Keep incomplete views and the uniform-value failure. ## Viable alternatives and decisive privacy condition

**Minimal fee path:** owner-local independent proofs plus a newly specified native shared settlement can amortize verification, while retaining its disclosed inner output groups. It does not solve the observed co-output leak. Use the already identified two-action transcript to prove exact authorization, cross-action current NF uniqueness, output placement and fee/refund/backing equations.

**Privacy redesign candidate:** study established transaction-level value commitments/binding with separate spend and output components, generic hidden pairing and multiple genuinely independent payers. Each owner retains spend secrets; any joint binding/signing/proving step needs an explicitly established multiparty protocol. A coordinator that receives individually labeled requests may still learn their grouping without seeing spend witnesses. A public permutation does not erase previously published labels. A shared final-output digest alone does not prove each output was funded exactly once; hidden assignment/coverage is an unresolved relation obligation, not a detail to invent during implementation.

**Based App comparison:** it may aggregate independent intents under ordered shared-state settlement, but the same visible component grouping, fee authorization, operator disappearance, currentness and private unilateral-exit questions remain. Select by these requirements, not by runtime availability.

The smallest privacy-positive target is two independently initiated legitimate payments for which the **full declared observer transcript** does not determine the other payer's output assignment, backed by realizable owner-local authorizations rather than only arithmetic SAT. Counterparties can know their own payer; the redesign must prevent propagation to unrelated outputs. Keep invoice reuse, co-output, amounts, fee funding, timing, submission and fetch metadata in the frozen threat model.

There is an honest hard boundary: if a user cashes out before any other independent source exists, public funding/liability conservation can force ancestry. No cipher, fresh address, synthetic identity, compulsory balance or forced wait manufactures an independent source. [Kappos et al., USENIX2018 §6.3](https://www.usenix.org/system/files/conference/usenixsecurity18/sec18-kappos.pdf) demonstrates historical amount/time heuristics in deployed Zcash; it is evidence that usage matters, not a current-Orchard break or universal tracing theorem. Preserve timely unilateral exit and state its actual privacy/fee limit.

## Capacity exits, epochs and recovery

A spend-only/no-new-output design has a direct [Sapling bundle analogue](https://github.com/zcash/sapling-crypto/blob/88a7946b4a3066787776e11f0a502654167e022d/src/bundle.rs#L64-L81) and [final consensus format](https://zips.z.cash/zip-0225#transaction-format) with independent spend/output counts, historical membership anchor and explicit balance. Orchard's paired dummy outputs are not that analogue. For the current bounded design, a new no-append full-claim exit with reserve left must prove all private outputs zero, exact payout/fee and original real NF, while native authenticates both current NF insertions and carries CM state. It reveals full-claim/no-change shape and, under the one-real-input policy, consumed value=P+fee. It needs a new selected relation/policy, not deletion of checks.

Reserve exit capacity inductively before admission. The existing reachable-state bound `m+2*u<=2*n+1` can motivate a no-append argument: consuming at least one positive claim, adding no positive notes and inserting two NFs does not increase that left side. Check every admitted transition and both tree limits; the mathematical argument is conditional on relation truth, not a passing witness sample.

RAILGUN's [tree rollover](https://github.com/Railgun-Privacy/contract/blob/36bcf5ed7cf94bfafb6e1a303e1832c769c16780/contracts/logic/Commitments.sol#L230-L255) retains historical roots and per-tree nullifier mappings. [Root/duplicate checks](https://github.com/Railgun-Privacy/contract/blob/36bcf5ed7cf94bfafb6e1a303e1832c769c16780/contracts/logic/RailgunLogic.sol#L420-L513) use the bound source tree, including old trees. Adapt only as an explicit authenticated forest/epoch scheme: retain old liabilities, root acceptance, NF spentness and owner witnesses. This is growing authenticated state, not a proof of constant total storage. A fresh epoch/NF namespace must not make an old claim spendable again.

Pruning, CAS hashes and valid roots do not supply missing receipts, proof parameters or executable bytes. Preserve exact historical positions, reorg undo/current acceptance and complete public reconstruction data; stronger backup contents or archives are explicit dependencies if seed-only recovery cannot reconstruct them. Local mirrors/chunks demonstrate transport, not independent retention. These obligations follow [issues8/9/10/23](https://github.com/olafweller/kaspa-privacy-initiative/issues/10), not an admin recovery key. All10 inspected issues remain open; source review closes none by implication.
