# Adversarial second pass and claim boundaries

This is a component feasibility screen with public unfunded fixtures. No native KAS architecture, instance, private-note circuit, reserve policy or security invariant is changed.

- **Inflation/value release:** existing Transaction/TxBody, kernel and stealth sum validators ran. Removed outputs fail transaction balance. Declared local peg-ins are not accepted-chain backing, and these results authorize no native reserve release. Integer test amounts are fixed tiny values; the harness is not a general payment API.
- **Double spending:** duplicate aggregation rejects through existing upstream duplicate checks. Individual input IDs remain publicly visible. The screen has no accepted UTXO database and cannot establish current unspentness or cross-block/reorg safety.
- **Authorization/recipient spendability:** the first test helper generated receiver keys inside senders, so its C1 marker never established recipient isolation. That finding is retained. The separate extension uses independently created recipient public addresses; actual recipients recover one output and sign a corresponding spend with their own derived private key. Fresh verifiers accept those spends. The known-address adapter follows existing upstream recovery primitives/checks; it is not the DB-backed wallet, a seed-backup recovery system or an exhaustive malicious-sender proof.
- **Privacy:** the final format contains global vectors and summed offsets, but that alone proves no unlinkability. Inputs/spent IDs, keys, commitments, masks/tags, signatures and kernels remain public. All tested sender/receiver output keys are distinct; this is observed wallet behavior, not a consensus anonymity rule. Anyone retaining pre-aggregation components retains their complete input/output/kernel mapping. Singleton, public funding, timing, fee and amount side information remain unresolved. No privacy score, human-identity claim or original-target qualification is inferred.
- **Missing dependency/data:** source/dependency hashes select the tested bytes, not continued availability. Missing software/history, wallet metadata or recipient keys is not zero balance or authority for an operator rescue. No cold wallet restore, independent durable hosting or parameter retention follows from these tests.
- **Stale state/reorg:** no node/chain currentness is modeled. A valid public transaction can refer to spent/unaccepted local inputs. Future integration needs independently authenticated current state and rollback behavior; the component validator alone does not supply them.
- **Hidden trust assumptions:** honest host/process/file isolation, pinned upstream/compiler/dependencies and installed OpenSSL entropy provider. Source/ELF hashes do not defeat a malicious host writer/debugger. The recipient actor keys stay resident and are not exported; that observation is not protection against a hostile root user. No new primitive or proof-system soundness claim is made.

The frozen capacity packet and prior failed privacy studies remain unchanged. Any future native-KAS use of value commitments plus hidden membership/spentness/transaction binding requires a separate reviewed design rather than copying MWEB's public spent-output model or merely wrapping these library calls.
