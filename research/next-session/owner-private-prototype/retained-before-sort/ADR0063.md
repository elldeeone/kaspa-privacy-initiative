# ADR-0063: Build an unfunded owner-private payment constructor

**Status:** Accepted for the bounded unfunded prototype after root second-pass
review. This selects an implementation contract, not a security approval.
**Date:** 2026-10-24 UTC. **Baseline:** `212378eee9681c2b1aed31b0276c39d211f18e82`.
**Origin:** [RFC0026](../rfc/0026-owner-private-multiparty-construction.md).

## Decision and purpose

Build one integrated, **unfunded** three-owner/six-output prototype in
`poc/owner-private-payments`, with additive evidence under
`research/next-session/owner-private-prototype`. Replace the action/output
partition in this new domain with independently proved spends and outputs,
stock malicious MPC over complete private output tuples and their aggregate
blinding adjustment, and post-mix spend proofs authorizing the complete
financial effects. Then attack the actual coordinator-visible transcript.

This is not a migration of the funded profile, a testnet broadcast, a new
asset or mainnet code. Existing funded source/keys/backups/profiles and sealed
research packets remain unchanged. No original wallet backup or private asset
is an input. Root can accept this prototype decision under the user's existing
authorization; it does not require another user permission ceremony.

The normative component contract is [CONTRACT.md](../../research/next-session/owner-private-prototype/CONTRACT.md).
It fixes the following choices:

1. Coherent Arkworks **0.6.0** BN254 Groth16 with separate Spend200 and
   Output168 statements. Each statement is SHA256-hashed **inside** its circuit
   and represented by two exact 128-bit little-endian public field elements.
   The spend statement contains no output-subset digest or public note key.
2. Existing Arkworks normalized BabyJubjub Pedersen commitments, native to
   BN254's scalar field. Stock one-window/64-bit Pedersen setup uses the fixed
   public ChaCha20 transcript specified in the contract. It samples points by
   coordinates and cofactor clearing; **never derive R as a public scalar times
   V**. Independently check canonical encodings, subgroup, identity and V/±R.
   All 256 secret blinding bits must represent a canonical scalar below the
   BabyJubjub subgroup order; gadget truncation is not a range check.
3. Fresh input CV blindings per spend/attempt, proved against the owned note's
   committed value. Retain the Note168/Receipt216/CF264 wallet format under the
   new domain; recipients need no previous output-CV opening to spend later.
4. Stock MP-SPDZ v0.4.4 live malicious MASCOT, over the **BabyJubjub** subgroup
   prime, takes two complete private output rows and one beta from each owner.
   Its existing six-row `secure_shuffle()` and checked openings reveal only
   six complete mixed rows and global Delta. No plaintext uploader-to-tuple
   map, individual beta or beta point crosses the coordinator boundary.
5. **Effects-only spend authorization, selected by root.** After checking every
   financial effect and their own payment/change inclusion, owners create
   Spend proofs bound to the same recomputed EffectsDigest. That digest includes
   every complete output tuple **including Output proof bytes**, while omitting
   Spend proof bytes and its own derived field. No extra BIP340/public native
   key or Binding signature is published. Valid Spend-proof witness malleability
   is explicitly allowed; this is not literal wire-byte authorization.
6. A new pinned RISC0 guest verifies all three Spend and six Output proofs,
   current-state/NF/CM transitions, canonical public context and the **direct**
   group conservation equation. The native journal separately binds the actual
   complete body and all proof bytes. Its new covenant/profile pins this guest;
   no host verdict, generic mix confirmation or coordinator signature authorizes
   funds. First mode P0 has one reserve input, one continuing reserve output,
   exact public fee and **zero native payout**. Exits/broadcasts are not selected
   by this prototype and existing independent exits are not replaced.

## Established work reused, adapted and rejected

The [source comparison](../../research/next-session/owner-private-prototype/CONTRACT.md#source-basis)
records the previously inspected Kaspa/Toccata/vProgs and mature privacy work,
plus current official library source. Reuse Sapling's separate spend/output
value-commitment responsibilities; ValueShuffle's confidential complete-output
construction, global balance checking, checks-before-authorization and fresh
retry discipline; and existing malicious MPC rather than inventing a mixer.
Adapt their composition and proof statements to the existing BN254/native
route. This does not inherit either protocol's security proof.

Reject the installed grouped action relation for this experiment, a central
all-witness builder, per-owner beta publication, public permutations, arbitrary
scalar-to-generator derivation, generic confirmation flags, unchecked MPC and
caller-selected verification keys. No new privacy token, privileged exit,
vProgs runtime or mainnet deployment is introduced.

## Explicit assumptions and limits

At least two eligible honest owners are required against the coordinator plus
one participant; all-but-one collusion is a retained negative control. The
coordinator sees endpoints, counts, schedules and final public components.
Three isolated same-host workers do not establish independent operators or
protection from malicious host/daemon administration. Fixed parameter derivation,
Groth16 setup/provenance, library soundness and the discrete-log assumption
remain trust assumptions. No adaptive-corruption, erasure, fairness, anonymous
network transport or robust termination claim is made.

The Output proof binds the ciphertext hash; it does **not** prove NaCl sealed-box
encryption correctness. Recipient-side decryption, invoice/note reconstruction,
CM matching and Output-proof verification are mandatory before treating a
delivery as a valid received payment. Sender-generated malformed delivery must
be detectably rejected under I-14; it cannot silently become a wallet balance.

An attempt may safely abort without blame or a survivor sum. Retry uses fresh
session/MPC material, input blindings and complete output material, preserving
accepted-note authority, backup, original positioned NF and financial setup.
After financial authorization, no protocol error path reveals that honest
owner's tuple mapping. A previously authorized valid body can still settle
after timeout; reconcile current accepted state/NFs, and report unknown results
as INCOMPLETE. There is no signature/proof revocation or rollback promise.

## Completion and adversarial review

Root's second-pass acceptance permits source implementation against this
contract. Source/circuit/generator/native seams receive an adversarial review
before expensive proof/setup execution; retain failures without weakening checks.
Root schedules useful CPU/GPU work. Operational caps/waits can produce
INCOMPLETE, never financial acceptance or a privacy pass.

The integrated positive must have six exactly-once mixed outputs, nine genuine
proofs, equal independently recomputed EffectsDigest, owner-local witness
construction and acceptance by the actual new unfunded native predicate.
Measure proof time, native verification, body size and fees. Prove owner-local
recipient recovery and repeat spending in this new domain before claiming those
features. A mock proof, a byte shuffle or the earlier successful sum is not
completion.

Freeze attack inputs/observer/truth/decision rules before inspecting outcomes:
wrong ranges/CVs/Delta/proofs; omission, substitution and duplication; spent or
duplicate original NF; stale/cross-domain/context replay; changed reserves,
fees, payouts or effects; missing final owner proof; party loss; and late
disclosure/retry with an old potentially publishable body retained. Distinguish
allowed witness changes from changed financial meaning. Preserve prior privacy
failures/thresholds and transparent entry/exit limitations. Passing bounded tests
does not establish cryptographic security or a complete private native-KAS
payment system.
