## Why the narrow claim is supported

- **Observed versus derived values are distinguishable.** Mode, nullifier/commitment slots, anchor count/root and authorization amounts come from explicit byte slices (`native_surface.py:169–175`). Old/successor state fields are decoded at `55–61,155–168`. Funding, reserve and payout values are cross-checked against selected native inputs/outputs (`178–218`). Reserve value, event ordinal, commitment positions and digest limbs are derived from these retained inputs, not independently native fields. In particular, commitment position zero comes from the separately pinned descriptor (`112–114,138`); the parser does not reconstruct or authenticate that initial commitment from the state root. No such cryptographic claim should be inferred.
- **Missing fields remain missing.** Event minute, funding group and bridge are null (`227–230`); roles/adversaries are null and directory/participant-view absence is explained (`252–260`). The schema requires these null fields and rejects extra model-event properties (`observation-parity.schema.json:64–175`). Timestamps remain raw receipt metadata. The native bootstrap count is retained rather than reset to fit the model.
- **No plausible-value fallback was found.** Native transaction/input/output envelopes use closed key sets (`69–92`); bytes and decimal strings are canonicalized and bounded (`21–40`). Missing accessed keys fail rather than default to zero; absent parents, bad framing and unsupported modes fail explicit checks. Descriptor/header metadata is not exhaustively schema-validated, but ignored metadata does not become timing, role or ownership values. This is a pinned-layout parser, not a generic native validator.
- **Proof and chain limits are explicit.** All six verification flags are false (`245–251`) and constrained false by the schema (`29–62`). The proof-byte mutation control deliberately passes structural parsing while changing its observed hash (`check_fixture.py:85–96`). Ciphertext digest checking and proof/ciphertext presence do not establish encryption, proof, covenant, transaction-ID, full-hash, public-witness or chain validity.
- **Controls match the limited claim.** Existing controls cover broken cipher binding, funding amount, reserve outpoint, mode and payout value (`check_fixture.py:98–108`), plus null missing fields and raw-region round trips (`39–61`). They are useful targeted checks, not exhaustive parser validation or JSON Schema execution. The schema alone is not an authentication or consistency checker for nested native metadata.

The saved artifact covers 15 serialized transaction bodies and 13 v6 operations, with 17 mapped field categories and 91 raw-byte references. Its evidence table and future protocol keep current-network, current wallet, proof and privacy conclusions separate (`46–67`).
